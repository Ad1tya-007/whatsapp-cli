# wacli 1.0.2

Release notes for the reliability fixes shipped after send/list failures against current WhatsApp Web.

## Summary

Auth worked, but `send` and `list` failed with opaque WhatsApp Web errors (`r`), and successful sends crashed on exit with `TargetCloseError`. 1.0.2 fixes message delivery, chat listing, session handling, and clean shutdown.

## Fixes

### Send messages
- Resolve recipients with `getNumberId()` instead of hard-coding `number@c.us`
- Send via `client.sendMessage()` using the returned LID/`_serialized` id
- Support WhatsApp Web’s July 2026 ID rename (`_serialized` → `$1`) via a patched `whatsapp-web.js` build

### List chats
- Stop using broken `client.getChats()` / `getChatModel` path
- Read chat metadata directly from WhatsApp Web’s Store
- Show the **5 most recent** chats (name, group/DM, unread count)

### Session & shutdown
- Persist auth under `~/.wacli` so the CLI works from any working directory
- Clear stale Chrome `SingletonLock` files left by unclean exits
- Always destroy the client in `finally`
- Remove page listeners before destroy to prevent `TargetCloseError` after a successful send
- Migrate legacy `./.wwebjs_auth` sessions into `~/.wacli` when present

### CLI / DX
- Surface real error messages instead of only “Failed to …”
- Bump CLI `--version` to `1.0.2`
- Update TypeScript config: `module` / `moduleResolution` → `Node16` (replaces deprecated `node` / `node10`)

## Dependency

- `whatsapp-web.js` pinned to  
  `github:lindionez/whatsapp-web.js#feat/fix-_serialized-id-fallback`  
  until the `$1` ID fallback lands in an official npm release

## How to verify

```bash
npm install
npm run build
npm link   # if using the global wacli binary

wacli list
wacli send -n <countrycode><number> -m "Hello from CLI"
```

First run after upgrading may show a QR code if the previous session was cleared or corrupted.
